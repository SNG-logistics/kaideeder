# พิมพ์ผ่านเครื่องพิมพ์ในตัวของแท็บเล็ต SUNMI (KAIDEEDER POS APK)

คู่มือนี้อธิบายว่าทำไมหน้าขาย (`/pos`) ที่เปิดในแอป Android ถึงพิมพ์ไม่ออก และต้องทำอย่างไร
ให้ใบเสร็จออกจากเครื่องพิมพ์ในตัวของ SUNMI D2s Plus (และรุ่นอื่นที่มี inner printer)

โปรเจกต์ฝั่ง Android อยู่ที่ `kaideeder-pos-android/` — รายละเอียดการ build / sign / ADB
อยู่ใน `README_ANDROID_POS.md` ที่ root ของ repo เอกสารนี้เน้นมุม "ทำยังไงให้พิมพ์ออก"

---

## 1. ทำไมพิมพ์จากแอปไม่ออก

หน้าขายรันอยู่ใน Android **WebView** ไม่ใช่ Chrome — ในนั้น

- `window.print()` **ไม่ทำอะไรเลย** (WebView ไม่มี print dialog)
- `window.open()` **ไม่เปิดหน้าต่างใหม่** — แอปปิด multiple windows ไว้ URL จะถูกโหลดทับ
  หน้า POS แทน (และถ้าเป็น `window.open('')` จะทำให้หน้าขายกลายเป็นหน้าว่าง)
- เครื่องพิมพ์ในตัวของ SUNMI **ไม่มี IP** จึงสั่งผ่านเครือข่ายแบบเครื่องพิมพ์ครัวไม่ได้

ดังนั้นการพิมพ์ในแอปต้องผ่าน **JS bridge** ที่แอปฉีดเข้ามาชื่อ `window.AndroidPOS`
(ดู `src/lib/android-pos.ts` ฝั่งเว็บ และ `PosJavascriptBridge.kt` ฝั่ง Android)

> ใน `ReceiptModels.kt` แล้ว build APK ใหม่ — ดูข้อ 6

## 3. ติดตั้งและตรวจสอบ (หน้างาน)

1. บนแท็บเล็ต SUNMI เปิดเว็บ → ล็อกอิน → **ตั้งค่า** → การ์ด **"KAIDEEDER POS สำหรับ SUNMI"** →
   ดาวน์โหลด APK (ไฟล์ล่าสุดใน `public/downloads/` ที่ workflow วางให้ การ์ดบอกเวอร์ชันเอง) แล้วติดตั้ง
   (อนุญาต "ติดตั้งแอปที่ไม่รู้จัก" ถ้าเครื่องถาม)
2. เปิดแอป **KAIDEEDER POS** — แอปจะโหลด `https://kaideeder.com/pos` เอง ล็อกอินตามปกติ
3. ไปที่ **ตั้งค่า** (ในแอป) → การ์ด **"เครื่องพิมพ์ในตัว SUNMI"**
   - ต้องขึ้น `✅ เครื่องพิมพ์ในตัว SUNMI พร้อมใช้งาน (READY)`
   - กด **ทดสอบพิมพ์** → ต้องได้กระดาษที่มีข้อความ ไทย / ລາວ / English อ่านออกครบ
4. เปิดโต๊ะ → เพิ่มเมนู → **ชำระเงิน** → ใบเสร็จต้องออกทันที และปุ่มจะเปลี่ยนเป็น
   "🖨️ พิมพ์ใบเสร็จซ้ำ"
5. กดพิมพ์ซ้ำ 1 ครั้ง → ต้องได้ใบที่มีหัว `*** REPRINT / สำเนา / ສຳເນົາ ***` และลิ้นชักไม่เด้ง

ถ้าการ์ดขึ้น `⚠️ หน้านี้ไม่ได้เปิดจากแอป KAIDEEDER POS` แปลว่าเปิดผ่าน Chrome / เบราว์เซอร์อื่น —
ต้องเปิดจากไอคอนแอป KAIDEEDER POS เท่านั้น bridge ถึงจะมี

## 4. ถ้ายังไม่ออก — เช็คตามรหัสสถานะ

รหัสมาจาก `AndroidPOS.getPrinterStatus()` / ผลลัพธ์การพิมพ์ (แสดงใน toast และการ์ดตั้งค่า)

| รหัส | ความหมาย | แก้ยังไง |
| --- | --- | --- |
| `READY` | พร้อมพิมพ์ | — |
| `BRIDGE_UNAVAILABLE` | ไม่มี `window.AndroidPOS` | ไม่ได้เปิดจากแอป หรือ APK เวอร์ชันเก่ากว่า 1.1.0 |
| `UNTRUSTED_PAGE` | หน้าไม่ได้โหลดจาก host ที่อนุญาต | URL ต้องเป็น `https://kaideeder.com/...` (ดู `ALLOWED_HOSTS` ใน `gradle.properties`) หรือหน้ายังโหลดไม่เสร็จ — รอแล้วลองใหม่ |
| `DISCONNECTED` | ยังผูกกับบริการเครื่องพิมพ์ไม่สำเร็จ | รอสักครู่แล้วกดตรวจสอบสถานะอีกครั้ง (แอปจะผูกใหม่ให้เอง) ถ้ายังไม่หาย ปิดแล้วเปิดแอปใหม่ |
| `SERVICE_NOT_FOUND` | มองไม่เห็นแอปบริการเครื่องพิมพ์ของ SUNMI | ถ้าเป็น APK เก่ากว่า 1.1.1 ให้อัปเดตก่อน (ดูหมายเหตุใต้ตาราง) ถ้าเป็น 1.1.1 ขึ้นไปแปลว่าเครื่องนี้ไม่มีบริการนั้นจริง ๆ ให้ใช้เครื่องพิมพ์ LAN แทน |
| `BIND_REFUSED` | ระบบปฏิเสธการเชื่อมต่อบริการ | รีสตาร์ทเครื่อง ถ้ายังไม่หายให้เช็คว่าแอปบริการเครื่องพิมพ์ถูกปิดใช้งานอยู่หรือไม่ |
| `UNSUPPORTED` (505) | เครื่องรุ่นนี้ไม่มี inner printer | ใช้เครื่องพิมพ์ LAN แทน |
| `OUT_OF_PAPER` | กระดาษหมด | ใส่กระดาษ 80mm (D2s Plus) |
| `COVER_OPEN` | ฝาเปิด | ปิดฝาให้สนิท |
| `OVERHEATED` | หัวพิมพ์ร้อน | พักเครื่องสักครู่ |
| `CUTTER_ERROR` / `CUTTER_RECOVERING` | ใบมีดตัดค้าง | เปิดฝา เอากระดาษที่ค้างออก ปิดฝา |
| `DUPLICATE_BLOCKED` | ต้นฉบับของออเดอร์นี้พิมพ์ไปแล้ว (หรือกดซ้ำเร็วเกิน 3 วิ) | ใช้ปุ่ม "พิมพ์ใบเสร็จซ้ำ" |
| `INVALID_REQUEST` | payload ไม่ผ่าน validation (ไม่มีรายการ, จำนวน ≤ 0, > 200 รายการ) | เช็คออเดอร์ — ทุกรายการที่ไม่ถูกยกเลิกต้องมี quantity > 0 |
| `PRINT_ERROR` / `NATIVE_ERROR` | SDK ของ SUNMI โยน error | ดู logcat (`adb logcat \| grep -E 'Sunmi\|kaideeder'`) |

> **สำคัญ — APK ก่อนเวอร์ชัน 1.1.1 ขึ้น `DISCONNECTED` เสมอบน Android 11 ขึ้นไป**
> ตั้งแต่ Android 11 ระบบซ่อนแอปอื่นจากกันเอง (package visibility) แอปที่ไม่ประกาศ
> `<queries>` ใน `AndroidManifest.xml` จะผูกกับบริการเครื่องพิมพ์ในตัวไม่ติด **โดยไม่มี error ใด ๆ**
> D2s Plus เป็น Android 11 จึงเจออาการนี้เต็ม ๆ กดทดสอบพิมพ์แล้วขึ้น `DISCONNECTED` ทั้งที่
> เครื่องพิมพ์ปกติดีทุกอย่าง แก้แล้วใน 1.1.1 โดยประกาศแพ็กเกจ `woyou.aidlservice.jiuiv5`
> ต้อง **build APK ใหม่แล้วติดตั้งทับ** ถึงจะได้ผล อัปเดตเว็บอย่างเดียวไม่พอ
> ตรวจว่าติดตั้งเวอร์ชันใหม่แล้วหรือยังด้วย `AndroidPOS.getAppVersion()` ต้องได้ 1.1.1 ขึ้นไป

เพิ่มเติม:

- ใบเสร็จออกแต่ **ภาษาไทย/ลาวเป็นสี่เหลี่ยม** → ไม่ควรเกิดกับ APK นี้ เพราะฝั่ง Android render
  เป็นรูป (`ReceiptFormatter.kt`, 576px = 80mm) ไม่ได้ส่ง text ให้ firmware — ถ้าเกิด แปลว่าเป็น
  APK/บิลด์อื่น
- ใบเสร็จ **ไม่ตัดกระดาษ** → เปิด "ตัดกระดาษอัตโนมัติ" ในการ์ดเครื่องพิมพ์ใบเสร็จ (ค่า `autoCut`
  ถูกส่งไปกับ payload เป็น `options.cutPaper`)
- **ลิ้นชักไม่เปิด** → ค่าเริ่มต้นของ APK ปิดไว้ (`CASH_DRAWER_ENABLED=false` ใน `gradle.properties`)
  ต้อง build APK ใหม่โดยเปิดค่านี้ก่อน และ reprint จะไม่เปิดลิ้นชักเสมอ

## 5. เมนูอาหารไม่แสดงในแอป (ที่แก้ไปพร้อมกัน)

WebView ของ SUNMI (Android 11, ไม่มี Google Play) ใช้ Chromium ประมาณ 83 และไม่อัปเดต
CSS ใหม่ ๆ ใน inline style ของ React จึงไม่ถูก autoprefix — `inset`, `100dvh`, flex `gap`
ทำให้ overlay เมนูสูง 0 หรืออยู่นอกจอ โค้ดหน้า POS ถูกแก้ให้ใช้ `top/right/bottom/left` และ
`100vh` (มี `100dvh` ทับใน `globals.css`) แล้ว — ดูกติกาใน `CLAUDE.md` › Conventions ›
"Old Android WebView compat"

## 6. ฝั่ง Android — ถ้าต้องแก้ APK

- โค้ด: `kaideeder-pos-android/app/src/main/java/com/kaideeder/pos/`
  - `PosJavascriptBridge.kt` — method ที่ JS เรียกได้ (ทุก method คืน JSON `{ ok, code, message }`)
  - `SunmiPrinterManager.kt` — bind `InnerPrinterManager`, สั่งพิมพ์ bitmap / ตัดกระดาษ / ลิ้นชัก
  - `ReceiptFormatter.kt` — วาดใบเสร็จเป็น bitmap 576px
  - `ReceiptModels.kt` — schema v1 ของ payload (validate ขนาด ≤ 256KB, 1–200 รายการ)
  - `PosWebViewManager.kt` — WebView + host allow-list + inject bridge ชื่อ `AndroidPOS`
- **`AndroidManifest.xml` ต้องมี `<queries>` ประกาศแพ็กเกจ `woyou.aidlservice.jiuiv5` เสมอ**
  ถ้าลบออกหรือเปลี่ยนชื่อแพ็กเกจ การผูกบริการเครื่องพิมพ์จะพังเงียบ ๆ บน Android 11 ขึ้นไป
  ค่านี้ต้องตรงกับ `SunmiPrinterManager.PRINTER_SERVICE_PACKAGE`
- ค่าตั้ง: `kaideeder-pos-android/gradle.properties` (`POS_BASE_URL`, `ALLOWED_HOSTS`,
  `CASH_DRAWER_ENABLED`, ...)
- build: JDK 17 + Android SDK 34 → `./gradlew testDebugUnitTest assembleDebug` (ดู `README_ANDROID_POS.md`)
- APK ที่แจกให้ร้านโหลดอยู่ที่ `public/downloads/` — workflow `Build SUNMI POS APK` เป็นคน commit
  ไฟล์ + manifest (`kaideeder-pos-sunmi.json`) ให้เองเมื่อ `versionName` เปลี่ยน การ์ด
  `AndroidPosDownloadCard` อ่าน manifest ตอนเปิดหน้า ไม่ต้องแก้โค้ดเว็บ **จะออกเวอร์ชันใหม่ต้องบัมป์ `versionName`**

ฝั่งเว็บ ทุกอย่างที่คุยกับ bridge อยู่ใน `src/lib/android-pos.ts` เท่านั้น
(`isAndroidPOSApp`, `printAndroidPOSReceipt`, `reprintAndroidPOSReceipt`,
`buildAndroidPOSReceiptPayload`, `getAndroidPOSPrinterStatus`, `testAndroidPOSPrint`,
`printAndroidPOSStationTicket`) — ห้ามเรียก `window.AndroidPOS` ตรง ๆ จาก component

## 7. สลิปครัว — เครื่องพิมพ์ครัว SUNMI NT311 (หรือเครื่องพิมพ์ ESC/POS ที่มีพอร์ตแลน)

ครัวไม่มีจอ กระดาษคือช่องทางเดียวที่ครัวจะรู้ว่ามีออเดอร์ ตั้งแต่ APK **1.2.0** แท็บเล็ตเป็นคน
ส่งสลิปไปเครื่องพิมพ์ครัวเอง (เดิมให้เซิร์ฟเวอร์ส่ง ซึ่งอยู่ที่ดาต้าเซ็นเตอร์ ยิงไป 192.168.x.x
ของร้านไม่ถึง และส่งเป็นตัวหนังสือแบบยุโรปทำให้ชื่ออาหารไทย/ลาวเพี้ยน — ถอดออกแล้ว)

### 7.1 ต่อสาย — ทุกเครื่องเกาะเราเตอร์ตัวเดียวกัน

```
              อินเทอร์เน็ต
                   │
              ┌────┴────┐
              │ เราเตอร์ │
              └──┬───┬──┘
        สายแลน  │   │  สายแลน
       ┌────────┘   └────────┐
       │                     │
 แท็บเล็ต D2s          เครื่องพิมพ์ครัว
  (แคชเชียร์)              NT311
 รับเลขจากเราเตอร์      192.168.1.51 คงที่
```

- **ห้ามต่อสายตรงจากแท็บเล็ตเข้าเครื่องพิมพ์** ถึงจะเสียบได้ก็ตาม — แอนดรอยด์มักถือสายแลนเป็น
  ทางออกหลักทันทีที่เสียบ ทั้งที่สายนั้นไปได้แค่เครื่องพิมพ์ หน้าขายจะโหลดไม่ขึ้น และต้องตั้งเลขเอง
  ทั้งสองฝั่งโดยไม่มีอะไรบอกเมื่อตั้งผิด
- ถ้าลากสายจากเราเตอร์เข้าครัวไม่ถึง ให้เครื่องพิมพ์เกาะ **ไวไฟของร้าน** แทน (NT311 รองรับ WLAN)
  เสียบสายชั่วคราวเพื่อเข้าหน้าเว็บของเครื่องพิมพ์ ตั้งชื่อไวไฟ/รหัส แล้วตั้ง IP คงที่เหมือนกัน
  ฝั่งโค้ดไม่ต่างกัน เพราะแท็บเล็ตยิงไปที่ IP เดียวกัน

### 7.2 ตั้ง IP เครื่องพิมพ์ให้คงที่ (ทำครั้งเดียว)

1. เสียบสายแลนจากเราเตอร์เข้าเครื่องพิมพ์ ไฟแลนต้องติดนิ่ง
2. กด **ปุ่มจับคู่ที่เครื่องพิมพ์สองครั้งติดกัน** → เครื่องพิมพ์รายงานเครือข่ายออกมาพร้อม IP ปัจจุบัน
   (ถ้าไม่พิมพ์อะไรออกมาเลย ปัญหาอยู่ที่สายหรือตัวเครื่อง แก้ตรงนี้ก่อน)
3. เอา IP นั้นพิมพ์ในช่องที่อยู่ของเบราว์เซอร์บนอุปกรณ์ที่อยู่วงเดียวกัน → หน้าตั้งค่าของเครื่องพิมพ์
   (รหัสผ่านครั้งแรกเว้นว่าง)
4. เปลี่ยนเป็นเลขคงที่ เช่น `192.168.1.51` — ถ้าวงของเราเตอร์ไม่ใช่ `192.168.1.x` ให้ใช้วงเดียวกับ
   ที่รายงานพิมพ์ออกมา เปลี่ยนแค่ตัวท้ายเป็น `51`
5. กดปุ่มจับคู่สองครั้งอีกรอบ ยืนยันว่าเลขเปลี่ยนแล้วจริง

### 7.3 ตั้งค่าในระบบ

**ตั้งค่า › เครื่องพิมพ์ครัว / บาร์ (สลิปออเดอร์)** (เก็บในฐานข้อมูลของร้าน ใช้ร่วมกันทุกเครื่อง)

- ใส่ IP เครื่องพิมพ์ครัว → กด **ทดสอบ** (ต้องกดจากในแอปบนแท็บเล็ต) → ต้องได้กระดาษจากเครื่องครัว
  ที่อ่านไทย/ลาวได้ครบ
- เปิดสวิตช์ **พิมพ์อัตโนมัติ** แล้วบันทึก
- **ยังไม่มีเครื่องพิมพ์บาร์ → เว้นช่องบาร์ว่าง** เครื่องดื่มจะพิมพ์รวมในสลิปครัวใต้หัวข้อ
  “เครื่องดื่ม / DRINKS” วันหน้ามีเครื่องบาร์ค่อยใส่ IP ระบบแยกสลิปให้เอง

### 7.4 มันทำงานยังไง (เพื่อรู้ว่าอะไรต้องเปิดค้างไว้)

- ตัวพิมพ์อยู่ในหน้าเว็บ (`src/hooks/useStationAutoPrint.ts`) ทำงานเฉพาะในแอปบนแท็บเล็ต ทุกครั้งที่
  มีสัญญาณออเดอร์อัปเดต (และทุก 20 วิเผื่อสัญญาณหลุด) จะดึงคิวครัว แล้วพิมพ์ **เฉพาะรายการที่ยัง
  ไม่เคยพิมพ์** (จำไว้ในเครื่องแท็บเล็ต) — จึงครอบคลุมทั้งกดส่งครัวจากหน้าขาย, QR รอบแรกหลัง
  แคชเชียร์ยืนยัน, QR รอบสั่งเพิ่มที่ไหลเข้าครัวเองโดยไม่มีใครกด, รวมรอบ และเดลิเวอรี่
- **แท็บเล็ตต้องเปิดแอปค้างไว้** (หน้าขายหรือหน้าหลังร้านก็ได้) เพราะมันเป็นคนส่งงานพิมพ์ ปิดแอป
  สลิปไม่ออก แต่จะออกตามมาทั้งหมดเมื่อเปิดแอปใหม่
- พิมพ์ย้อนหลังเฉพาะรายการที่ถูกเพิ่มภายใน 3 ชั่วโมง — เปิดใช้ครั้งแรกหรือล้างข้อมูลแอปจะไม่พ่นออเดอร์เก่าทั้งร้าน
  (ต้องรัน `npx prisma db push` ตอน deploy เพราะเพิ่มคอลัมน์ `order_items.createdAt` — ถ้ายังไม่รัน คิวครัวจะ error และไม่มีอะไรพิมพ์)
- แท็บเล็ตสองเครื่องเปิดแอปพร้อมกัน = สลิปออกสองใบ — ร้านนี้มีเครื่องเดียว

### 7.5 ถ้าไม่ออก — รหัสจากปุ่มทดสอบ / toast

| รหัส | ความหมาย | แก้ยังไง |
| --- | --- | --- |
| `APP_UPDATE_REQUIRED` | APK เก่ากว่า 1.2.0 | บิลด์จาก GitHub Actions แล้วติดตั้งทับ |
| `PRINTER_UNREACHABLE` | ต่อไม่ถึง IP นั้น (ปฏิเสธ/ไม่มีเส้นทาง) | IP ผิดวง, เครื่องพิมพ์ปิด, สายหลุด — กดปุ่มจับคู่สองครั้งดู IP จริง |
| `PRINTER_TIMEOUT` | รอ 5 วิแล้วเงียบ | เครื่องพิมพ์ปิดหรืออยู่คนละวงกับแท็บเล็ต เช็คว่าทั้งคู่เกาะเราเตอร์เดียวกัน |
| `NETWORK_PRINT_ERROR` | ส่งข้อมูลไม่จบ | สายหลวม / เครื่องพิมพ์ค้าง ปิดเปิดเครื่องพิมพ์ |
| `RESULT_TIMEOUT` | แอปไม่รายงานผลกลับใน 45 วิ | คิวงานพิมพ์ค้าง ปิดแล้วเปิดแอปใหม่ |
| `INVALID_REQUEST` | IP/พอร์ต หรือรายการไม่ผ่านตรวจ | ใช้รูปแบบ `192.168.1.51` หรือ `192.168.1.51:9100` |

พิมพ์ออกแต่ **ไม่ตัดกระดาษ** → เครื่องพิมพ์รุ่นนั้นไม่รู้จักคำสั่ง `GS V 66` — ฉีกที่รอยปรุแทน หรือ
แก้ `EscPos.cutPaper()` เป็น `GS V 1`
